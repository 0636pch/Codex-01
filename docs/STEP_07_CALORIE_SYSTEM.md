# STEP 7 — 칼로리 시스템

## 목표
섭취량과 소비량을 분리해 보여주고, 극단적인 칼로리 적자를 경쟁이나 EXP 보상으로 만들지 않는다.

## BMR
인바디 BMR이 있고 30일 이내이면 표시값으로 사용할 수 있다. 없으면 Mifflin-St Jeor 공식을 사용한다.

- 남성: `10W + 6.25H - 5A + 5`
- 여성: `10W + 6.25H - 5A - 161`
- 성별 미공개: 두 공식의 중간값을 추정치로 사용

W=kg, H=cm, A=만 나이.

## 일상 활동 소비
운동을 제외한 활동계수를 사용한다.

| 활동 수준 | 계수 |
|---|---:|
| 매우 낮음 | 1.20 |
| 낮음 | 1.30 |
| 보통 | 1.45 |
| 높음 | 1.60 |

`일상활동kcal = BMR × (활동계수 - 1)`

운동 칼로리를 별도 더하므로 일반 TDEE 계수보다 보수적인 값을 사용한다.

## 운동 소비
MET 데이터가 있는 활동:
`kcal = MET × 3.5 × 체중kg / 200 × 운동분`

웨이트는 시간과 강도에 따라 기본 MET 3.5~6.0을 사용하되 최대치를 제한한다. 웨어러블 값이 있으면 출처를 표시하고 원본과 추정값을 구분한다.

## 하루 계산
- `총소비 = BMR + 일상활동 + 운동소비`
- `섭취 = 음식기록 kcal 합`
- `칼로리밸런스 = 섭취 - 총소비`

예: 2,120 섭취, 2,790 소비 → -670 kcal.

## 영양소
음식별 탄수화물·단백질·지방·식이섬유를 합산한다. 영양소가 비어 있어도 칼로리 기록은 저장할 수 있고, 불완전 데이터임을 표시한다.

## 안전
- 적자가 클수록 EXP를 더 주지 않는다.
- 섭취 누락을 목표 달성으로 간주하지 않는다.
- 매우 큰 적자가 반복되면 비난 없이 기록 완전성 확인과 전문가 상담 안내
- 칼로리는 모두 추정값이며 진단이나 처방으로 표시하지 않는다.
- 임신, 미성년, 섭식장애 위험 등 개인화 의료 판단은 MVP에서 하지 않는다.

## 집계
음식·운동 기록 변경 시 Cloud Functions가 `dailySummaries/{dateId}`를 재계산한다. 사용자 시간대가 변경되면 영향을 받는 날짜를 다시 집계한다.

## 완료 기준
BMR, 활동, 운동 MET, 총소비, 섭취, 밸런스와 안전 원칙을 확정했다. 다음은 STEP 8 MVP 개발 순서다.
